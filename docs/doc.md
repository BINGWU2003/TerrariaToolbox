# 1. 项目概述

本需求更新于 2026-10-11，采用用户已批准的 1.1 Shizuku 方案与 1.2 完整第一版方案。原第一阶段“不使用 Shizuku”限制已扩展；第一阶段操作说明与测试记录作为历史资料保留。

## 1.1 项目名称

泰拉瑞亚工具箱（Terraria Toolbox）

应用显示名称为“泰拉瑞亚工具箱”，Android Studio 项目名使用 `TerrariaToolbox`。

## 1.2 项目目标

开发一款面向普通 Android 用户的轻量级《泰拉瑞亚》工具箱，提供统一的工具入口，并在文件访问方案验证可行后逐步扩展游戏辅助功能。

第一版以“中文切换”作为首个工具：在经过验证的设备上，用户完成文件访问授权后，应用直接备份并修改游戏配置，将语言切换为中文。后续可增加角色导入、世界存档导入等工具；这些功能属于后续规划，不纳入第一版验收。

第一版中文切换工具的目标配置文件：

```text
/storage/emulated/0/Android/data/com.and.games505.TerrariaPaid/config.json
```

优先实现“一次授权，后续直接修改原文件”。授权能否复用以系统实际行为为准，失效后引导重新授权。无法直接写回时，提供导入、修改、备份和导出，并明确提示仍需使用 MT 管理器等工具手动替换。

**中文切换工具的直接写回是优先验证的核心能力；仅完成导出，不代表完成了一键切换。** 后续工具必须分别验证目标文件的访问和操作能力，不能直接沿用配置文件验证的结论。

## 1.3 目标用户与支持范围

- 第一版面向 Android 14 玩家，优先验证用户当前使用的手机和游戏版本。
- 直接模式优先使用用户主动启动并授权的 Shizuku；导入导出模式无需启动 Shizuku。不要求 Root、电脑或用户执行 ADB 命令。
- 第一版目标包名为 `com.and.games505.TerrariaPaid`；其他发行版本和包名暂不承诺支持。
- 直接写回仅在实际验证通过的设备和系统环境中列为支持功能，不因一台手机成功就承诺所有 Android 14 设备均可使用。

## 1.4 已确认事实与待验证事项

| 项目 | 当前结论 |
| --- | --- |
| 真实配置样本 | 项目中的 `config.json`，JSON 格式合法 |
| 语言字段 | 根对象中的 `Language`，区分大小写，值为整数 |
| 语言编号 | 用户确认：`1` 为英文，`7` 为中文 |

| MT 操作流程 | 用户反馈：进入 MT 时允许管理所有文件，访问配置时又出现“使用此文件夹／允许访问”授权 |

| 本应用访问能力 | SAF 在用户手机无法选择目标；1.1 改用用户授权的 Shizuku，用户反馈本机调试正常；具体设备与版本待补录 |
| 游戏实际生效 | 用户于 2026-10-11 确认中文切换、游戏内中文和完整恢复正常；应用及设备重启检查未单独记录 |

# 2. 技术方案

## 2.1 开发技术栈

- 主要语言：Kotlin；开发环境：Android Studio；界面框架：Jetpack Compose；构建系统：Gradle。
- JSON 处理：优先使用 `kotlinx.serialization` 的 JSON 树结构，保留未知字段和数字精度。
- 最低支持版本：Android 14（API 34，`minSdk = 34`），第一版优先完成 Android 14 真机验证。
- `compileSdk`、`targetSdk`：建项时明确设置并记录，兼容所选工具链；如上架，满足发布渠道当时的要求。不依靠降低 `targetSdk` 解决目录访问问题。
- 架构：单 Activity，按职责分层，不引入与第一版无关的复杂架构。

建议划分为：

- `ui`：页面、状态展示和交互。
- `data`：文件授权、URI 读写、备份存储与导入导出。
- `domain`：配置验证、语言识别、修改规则和结果校验。

## 2.2 文件访问与权限原则

直接模式优先使用 Shizuku，固定依赖 `api/provider 13.1.5`，要求服务 API 13+、shell UID 2000、主用户和主存储。独立 UserService 只提供固定游戏目标的探测和文件描述符访问，校验应用调用方，不接收任意路径或命令。保留 Storage Access Framework（SAF）目录和单文件授权入口；副本导入、导出统一使用系统文件选择与保存入口。

Android 标准规则限制通过 SAF 选择 `Android/data` 目录及其子目录中的文件；`MANAGE_EXTERNAL_STORAGE` 也不允许访问其他应用的专属目录。MT 的成功操作不能直接证明本应用可通过标准接口访问。

实现要求：

- 优先申请满足功能所需的最小范围读写授权；若目录或文件授权已足够，不申请“管理所有文件”权限。
- 不将 `READ_EXTERNAL_STORAGE`、`WRITE_EXTERNAL_STORAGE` 或 `MANAGE_EXTERNAL_STORAGE` 视为目标目录访问的保证。
- SAF 通过返回的 `content://` URI 和 `ContentResolver` 读写；Shizuku 固定定位标识经后端路由访问，不将展示路径作为任意路径入口。
- SAF 按实际授予权限请求持久授权；Shizuku 在手机重启后需重新启动并检查服务和授权，不显示为持久目录授权。
- 授权标记仅作参考，实际读写仍需捕获失败；正确处理拒绝、撤销、系统更新和提供方变化。
- MT 已获得的权限不会自动授予本应用，本应用必须独立验证授权与读写流程。
- 用户主动启用 Shizuku 无线调试模式无需 Root 或连接电脑，但依赖调试服务。应用不降级系统组件、不申请管理所有文件权限、不加入 Root、ADB 或其他限制绕过后端。开发设备连接不参与用户授权流程。

参考：[Android 11 文件访问限制](https://developer.android.com/about/versions/11/privacy/storage#document-access-restrictions)、[所有文件访问权限的范围](https://developer.android.com/training/data-storage/manage-all-files)。

## 2.3 配置识别与修改规则

第一版仅提供切换中文，英文编号用于识别和验证，不增加独立的“切换英文”入口。

| 输入 | 显示与行为 |
| --- | --- |
| `"Language": 1` | 显示“英文”，允许切换中文 |
| `"Language": 7` | 显示“配置已设为中文”，不重复写入；导入副本仍允许原样导出 |
| 其他整数 | 显示原值及“暂不支持的语言编号”，第一版禁止修改 |
| 字段缺失、字段名不匹配、字段不在根对象或类型错误 | 显示配置不受支持，禁止修改；不自动新增或猜测字段 |

修改要求：

- 使用 JSON 解析器，不使用全局文本替换或正则表达式修改字段。
- 根节点必须为对象，`Language` 必须为整数型 JSON 数值，不接受字符串 `"7"` 或小数 `7.0`。
- 不接受存在重复键的配置，避免解析后丢失或覆盖原始数据。
- 仅修改根对象的 `Language`；其他键值、类型、数组顺序和数字精度必须保持不变，未知字段必须保留。
- 输出允许空白和缩进变化，不要求与原文件逐字节相同；备份和完整恢复必须保留原始字节。
- 样本中的 `LastLaunchedVersion` 可作为备份信息和排查线索，不仅凭其内部编号判断具体发行版本。

## 2.4 工具扩展原则

- 将中文切换的界面和业务逻辑集中到独立功能目录，便于后续增加角色、世界存档等工具；第一版不要求拆分多个 Gradle 模块。
- 文件授权、URI 读写、原始字节备份和结果校验作为可复用能力，各工具保留自己的文件格式验证和操作规则。
- 备份记录除来源外，还需包含所属工具和文件类型，避免后续将配置备份误用于角色或世界存档恢复。
- 中文切换之外的工具不假设目标文件是 JSON，也不将所有文件操作固定到 `config.json`。
- 当前阶段不引入动态插件系统，也不预先实现未确定需求的存档解析和导入逻辑。

# 3. 功能需求

## 3.1 工具箱首页与中文切换页面

工具箱首页展示应用名称与版本，以及当前可用工具入口。第一版只展示可用的“中文切换”工具，后续新增工具以独立入口接入，不提供无法操作的占位按钮。

中文切换页面展示目标配置位置、当前文件来源、授权状态和识别到的语言。按状态提供一个主要操作：

| 状态 | 主要操作与提示 |
| --- | --- |
| 未选择或未授权 | “授权游戏配置”，同时提供“导入配置”备用入口 |
| 英文原文件，且授权方式已通过写回验证 | “切换中文”，说明会自动备份并写回原文件 |
| 英文副本或仅可读取 | “生成中文配置并导出”，说明需要手动替换 |
| 当前值为 `7` | “配置已设为中文”，允许刷新；导入模式允许导出当前副本 |
| 文件无效或授权失效 | 显示原因，提供重新选择、重新授权或导入入口 |

中文切换工具的备份历史、恢复、原始备份导出和使用说明放在该工具的次级入口。必须区分游戏原文件和导入副本，禁止仅凭文件名 `config.json` 判定为游戏原文件。

## 3.2 授权、选择与读取

- 引导用户选择目标配置所在目录或目标文件；系统拒绝时显示结果，不反复弹出授权界面。
- 校验文件名、来源和访问能力，记录实际 URI；不默默改用其他同名文件。
- 首次选择直接写回目标时，展示实际来源，要求用户确认对应游戏配置。
- 检查文件是否可读取、是否为空、JSON 是否合法、根对象及 `Language` 是否符合要求。
- 仅可读取时允许进入导出流程，不显示直接写回按钮。
- 用户取消选择属于未完成操作，不显示为“修改失败”。
- 读取、解析和保存不阻塞主线程；执行中禁用重复操作。

## 3.3 直接切换中文

在授权验证通过的设备上，用户点击“切换中文”后执行：

1. 提示用户先完全退出游戏，避免游戏覆盖配置；不监控或强行关闭游戏。
2. 重新读取目标文件并验证，使用最新内容，不直接覆盖页面缓存对应的旧内容。
3. 若 `Language` 已为 `7`，提示“配置已设为中文”，结束操作，不重复备份或写入。
4. 保存本次读取内容的原始字节备份，并回读校验完整性；失败则终止。
5. 将根对象的 `Language` 从 `1` 改为整数 `7`，验证其他字段未改变。
6. 写入前再次检查源文件内容哈希；若已变化，取消本次写入并提示重新加载。
7. 写回同一目标文件，捕获打开、写入、关闭及提供方返回的错误。
8. 重新读取目标文件，验证内容完整、JSON 合法、`Language` 为 `7`，其他配置与本次原始内容一致。
9. 显示“配置已保存，请启动游戏确认中文显示”。

内容检查只能降低并发覆盖风险，不能保证游戏运行时安全修改。安全写入要求见第 5 章。

## 3.4 自动备份与备份历史

- 每次生成修改后的配置前，保存源文件原始字节；恢复游戏原文件前，也必须备份当前内容。
- 备份存放在应用内部持久目录，不使用可能被系统清理的缓存目录。
- 每份备份具有唯一标识和时间信息，记录来源、原始语言、文件大小、内容哈希及可获得的游戏版本信息。
- 备份完成后回读并比对大小和哈希，确认成功后才继续修改或恢复。
- 不覆盖首次原始备份或已有备份；清理备份由用户主动操作并确认。
- 已是中文且不执行修改时不产生重复备份，用户仍可主动保存或导出备份。
- 提供备份列表和原始文件导出；说明应用卸载或清除数据可能导致内部备份丢失。

## 3.5 恢复配置

恢复是完整恢复备份文件，可能同时还原音量、按键等其他设置；执行前展示备份时间、来源及恢复范围。

直接恢复游戏原文件时：

1. 检查授权有效，确认目标与备份来源一致；来源不同则禁止一键恢复，允许导出备份供用户处理。
2. 校验备份完整性、JSON 格式及受支持的配置结构。
3. 读取并备份当前目标文件，确认备份成功；失败则取消恢复。
4. 写入前检查目标内容是否变化，变化时取消并要求重新加载。
5. 用备份的原始字节恢复，重新读取并比对内容哈希。
6. 成功后显示“已恢复游戏配置，请启动游戏确认”。

无写回权限时，只允许恢复应用内副本或导出备份，分别显示“已恢复编辑副本”或“备份已导出，尚未替换游戏配置”。

## 3.6 导入与导出备用流程

- 用户通过 MT 将原配置复制到可访问位置后导入，或选择其他可访问副本。
- 导入后使用与直接写回相同的 JSON 验证、语言规则和自动备份逻辑。
- 不修改导入源文件，只在应用内生成修改后的副本。
- 仅保存一个当前编辑副本，跨应用重启保留。有效新导入先确认替换并备份当前副本，取消、无效输入或保存中断保留此前副本；内容落盘核验后原子提交元数据引用。
- 副本备份记录可选 `workspaceId`；只恢复到同一副本。旧记录缺少字段时继续视为外部配置备份，不自动跨后端或跨副本恢复。
- 中文副本原样导出，不重复生成或自动备份；英文生成先保存原始字节备份，取消导出保留生成结果与备份并说明尚未导出。
- 使用系统保存文件入口导出，默认文件名为 `config.json`；禁止导出覆盖导入源、已知游戏原文件及可识别的文档 URI 别名。
- 导出后回读并校验；失败或无法回读时，明确说明结果未确认，不显示成功。
- 成功提示为“中文配置已导出，尚未替换游戏配置”，展示实际保存名称和位置。
- 指导用户完全退出游戏，用已验证可访问目标目录的 MT 替换原文件，确保最终文件名为 `config.json`，再启动游戏确认中文显示。
- 保存结果若为 `config (1).json` 等名称，明确提示替换时使用正确名称。
- 保留原始备份导出入口，便于手动恢复。
- 该流程在用户已确认可使用 MT 的环境中验证，不保证任意设备或文件管理器均可执行。

## 3.7 错误与操作结果

| 情况 | 提示与后续操作 |
| --- | --- |
| 用户取消授权或导出 | 提示“已取消”，不修改文件 |
| 目录受限、仅有读权限或授权撤销 | 说明无法直接写回，提供重新授权或导入导出 |
| 文件不存在、为空或不可读取 | 展示实际目标，引导检查位置或重新选择 |
| JSON 错误、重复键、语言字段缺失或类型错误 | 提示配置不受支持，禁止修改 |
| 语言编号未支持 | 展示原值，不猜测语言，不写入 |
| 备份失败、空间不足或校验失败 | 中止修改或恢复，提供清理空间、重试等操作 |
| 源文件在操作期间变化 | 取消本次写入，引导退出游戏并重新加载 |
| 写回失败、文件可能不完整或回读校验失败 | 不显示成功，提示暂勿启动游戏，保留原始备份并提供恢复或导出入口 |
| 导出失败或校验未通过 | 不显示导出成功，允许选择其他位置重试 |

错误提示采用用户能理解的语言。技术异常可保留在本地诊断记录中，但不得输出完整配置或用户标识。

# 4. 交互流程

## 4.1 首次授权与直接修改

打开工具箱 → 进入中文切换 → 授权目标配置 → 确认实际来源 → 读取并显示语言 → 完全退出游戏 → 点击切换中文 → 自动备份 → 修改并写回 → 回读验证 → 提示启动游戏确认。

## 4.2 再次使用

打开工具箱 → 进入中文切换 → 检查保存的授权 → 重新读取配置 → 已是中文则提示无需修改；为英文则进入备份和写回流程；授权失效则引导重新授权或导入。

## 4.3 导入与手动替换

使用 MT 复制原配置到可访问位置 → 应用导入 → 验证并自动备份 → 生成中文配置 → 导出并校验 → 完全退出游戏 → 使用 MT 替换原文件 → 启动游戏确认。

## 4.4 恢复

选择备份 → 展示来源和完整恢复范围 → 确认目标 → 备份当前配置 → 恢复并回读验证。无直接写回权限时，改为恢复编辑副本或导出备份后手动替换。

# 5. 非功能需求与数据保护

- 完全离线，不上传配置、不收集无关个人信息；第一版不需要网络权限。
- 配置中的用户标识仅用于原样保存，不显示在错误提示或完整输出到日志。
- 原始备份逐字节保留；修改结果按第 2.3 节保证非语言字段不变。
- 同一目标同一时间只允许一次修改或恢复操作。
- 在应用内部生成并校验完整候选内容后，再执行外部写入；内部备份使用安全落盘方式，避免将半写入备份当成有效备份。
- 外部提供方只有在已验证支持安全替换时才采用对应能力，不假设 SAF 支持原子重命名或事务写入。
- 仅能覆盖写入时，显式处理截断、短写入和中断风险。失败后保留原始备份；授权仍有效时提供恢复操作，否则提供备份导出。
- 不自动无限重试写入，不把失败后的不确定状态显示为成功。
- 应用重启后重新检查授权和目标内容；存在尚未完成验证的操作时提示检查或恢复，不沿用旧成功状态。
- 第一版不需要复杂动画、后台常驻、游戏进程监控或在线服务。

# 6. 验收标准

## 6.1 基础功能验收

1. 能在 Android Studio 中构建并安装至 Android 14 设备。
2. 能读取项目中的真实 `config.json`，显示“配置已设为中文”。
3. 用真实样本的副本，将 `Language` 改为 `1` 作为输入，应用能生成 `Language` 为整数 `7` 的输出；原样本不受影响。
4. 修改前后除 `Language` 外，其他字段、类型、数组顺序和数字精度一致，包括未知字段。
5. 原始备份与输入文件字节和哈希一致；备份失败时不继续修改或恢复。
6. 已是 `7` 时不重复写入；字段缺失、重复键、字符串、小数或未知编号时不修改。
7. 能导出并回读校验修改结果及原始备份，取消或失败时不显示成功。
8. 无直接写回能力时明确标注正在编辑副本，导出成功不显示为游戏切换成功。
9. 能在应用内恢复副本；备份历史清楚区分来源，完整恢复结果与备份原始字节一致。
10. 安装后的应用显示名称为“泰拉瑞亚工具箱”；首页能进入中文切换工具，并能从工具页面返回首页。

## 6.2 直接写回验收

以下项目通过后，才能在对应设备环境中声明支持一键修改：

1. 本应用独立取得 SAF 或 Shizuku 授权，不沿用 MT 权限。Shizuku 需验证服务 API、shell UID、主用户与固定目标；普通用户流程不依赖 Root 或电脑连接。
2. 实际读取、备份、写回和回读校验全部成功，修改的是用户确认的游戏原文件。
3. SAF 支持持久授权时检查应用及设备重启后的授权复用；Shizuku 检查应用重连、手机重启后重新启动服务及授权复用；失效时有重新连接或授权提示。
4. 恢复前成功备份当前文件，恢复后目标字节与选中备份一致。
5. 授权撤销、源文件变化、空间不足及写入中断时不误报成功，并提供有效备份的恢复或导出入口。
6. 完全退出游戏后，将英文配置改为中文，启动游戏确认显示中文；退出并重新启动游戏后仍保持中文。
7. 记录设备型号、Android 版本、安全补丁、游戏发行版本与包名、应用 `targetSdk`、文件提供方及授权入口。

## 6.3 手动替换流程验收

在用户当前可使用 MT 的设备上，完整执行“复制配置 → 导入 → 修改 → 导出 → MT 替换 → 启动游戏显示中文”，并验证可以用导出的原始备份手动恢复。

此项证明备用流程可用，不替代直接写回验收。

# 7. 开发前验证与风险处置

## 7.1 第一优先级：授权可行性

完整页面和业务开发前，先创建最小 Kotlin 测试程序。在用户当前手机上核对 MT 授权页面及实际授权范围，记录环境，并验证本应用：

- 是否能通过系统支持的目录或文件选择入口选到目标配置。
- 是否取得有效读写授权，是否能持久保留和复用。
- 是否能先读取并生成已校验备份，再写入并回读原文件。
- 对英文配置写入 `Language = 7` 后，游戏是否正常启动并显示中文。
- 授权取消、失效或提供方拒绝时，能否正确结束操作。

任何可能覆盖原文件的测试都必须先保存有效备份。记录手机型号、系统版本、安全补丁、MT 版本、游戏版本及授权入口。

验证结果应形成明确结论：

- 通过：将对应授权方式纳入主流程，并明确已验证设备范围。
- 未通过：记录失败步骤和原因，将该环境标为不支持直接写回；继续实现并验证 MT 配合的导入导出流程，不宣称已完成一键切换。

## 7.2 第二优先级：数据与版本兼容

- 用真实样本及其英文副本验证字段读取、修改和非语言字段保留。
- 检查浮点数、未知字段、数组、空对象、重复键和错误类型等情况。
- 检查完整恢复可能覆盖其他设置的提示与行为。
- 不把一个样本的完整字段集合固定为所有版本必须一致的结构。
- 后续增加其他包名、游戏版本或语言编号时，补充真实样本和游戏生效验证。

# 9. 第一版交付范围

## 9.1 必须交付

- Kotlin + Compose 原生应用源码、构建说明和可安装 APK。
- “泰拉瑞亚工具箱”应用名称、工具箱首页和中文切换工具入口。
- `Language = 1 / 7` 识别规则及切换中文功能。
- 自动原始备份、备份历史、应用内恢复及备份导出。
- 配置导入、修改结果导出、保存校验和 MT 手动替换说明。
- 清楚区分原文件、副本、配置保存、备份恢复、文件导出和游戏实际生效的状态。
- 当前目标设备的授权验证及完整流程验收记录。

## 9.2 验证通过后必须交付

- 游戏原配置的直接写回、回读验证和完整恢复。
- 系统允许时复用持久授权，失效时重新授权。
- 已验证设备、系统和游戏版本的支持说明。

若直接写回验证失败，交付说明必须明确“一键修改尚未实现或当前环境不支持”，不能仅以导出功能代替该能力的验收。

## 9.3 第一版不包含

- Root、ADB 用户访问后端或其他限制绕过方案。Shizuku 为已授权的直接模式访问方案。
- 多游戏、多包名、任意字段编辑及未经验证的其他语言编号。
- 独立的切换英文入口、配置模板生成、云同步和账号系统。
- 自动关闭游戏、后台常驻、在线更新检查或复杂文件管理功能。
- 角色导入、世界存档导入及其他尚未验证的工具功能。

## 9.4 后续扩展方向

在第一版实践验证通过后，可按实际需求逐步增加：

- 角色导入：选择角色文件，验证兼容性后导入游戏对应目录。
- 世界存档导入：选择世界存档，验证兼容性后导入游戏对应目录。
- 角色与世界存档备份、导出和恢复。

每个新工具开发前，必须取得真实文件样本，确认目标目录、格式、游戏版本兼容性、所需配套文件、重名冲突处理和写入前备份规则，并完成独立的权限与游戏生效验证。后续工具的详细需求在对应阶段另行补充。
