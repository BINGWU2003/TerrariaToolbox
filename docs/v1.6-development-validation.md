# 1.6 分服存档交互验证

日期：2026-10-11。版本：1.6 / versionCode 7。用户按 grilling 确认内置目录绑定所属服、禁止跨服、未知文件声明来源、ZIP 携带来源信息及最终界面方案后实施。

## 问题与实现

旧版本只枚举 players／worlds，遗漏新加入的 xd-worlds；暂存模型不保留来源服，确认目标后可以把所有内置资源写入另一服。旧测试甚至要求这条路径成功。

现在目录绑定国际服 players／worlds 与国服 xd-players／xd-worlds，后者角色目录暂缺时正常显示空状态。七份内置资源分为国际服四角色／两世界和国服一世界，不修改资源内容或按文件名推断游戏格式版本。

- 内置来源页先选所属服，再按角色／世界浏览。同服跨分类选择保留，切换所属服清空内置选择。国服角色分类明确提示暂无资源，并提供手机文件入口；现有国服游戏角色管理保留。
- StagedSave 携带来源服与识别依据。世界偏移 4–10 的已知 relogic／xindong 标记识别国际／国服；不进行完整格式有效性或目标游戏版本兼容性解析。
- 无法识别的角色或世界需用户明确声明；存在已知来源时声明不可冲突。选定来源后自动绑定同服目标，再连接并重新核实国服账号。重新连接时即使列表已加载也重新核实。
- 来源确认、清单确认与写入前均约束同服。写入前重新读取已知世界标记，Binder 适配层再次检查；混服或来源冲突整批停止。缓存检查失败进入结果页并清理暂存文件。
- 多文件 ZIP 的根目录 terraria-toolbox.json 记录 schema 1、所属服、路径、字节大小和 SHA-256。暂存时检查完整清单、大小、哈希及世界标记的一致性，元数据上限 256 KiB。来源信息不记录账号，不是签名认证。原单文件导出内容不变；旧 ZIP 可导入，未知来源需声明。
- 同名自动编号、独占创建、同步和 SHA-256 回读、64 MB／文件、256 MB／批、500 个存档的限制保留。底部导航、搜索排序、记住目标、国际服语言与内部异常恢复沿用 1.5。

## 验证边界

普通模拟器测试只使用隔离夹具、测试文档提供器与应用缓存，不写真实游戏目录。未在实体手机复测 Shizuku 文件访问及两种游戏实际加载这些存档。来源绑定用于阻止误导入另一服，不证明任意游戏发行版本能读取文件。来源声明由用户提供，ZIP 来源信息未经签名；本版没有转换或解密能力。

提供资源不包含地图探索、自动备份等附属文件；导入／导出仍只复制主存档。进程退出后需重新选文件，持久化目标版本与账号仍在连接后重新核实。
