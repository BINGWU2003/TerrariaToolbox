# 1.4 存档管理验证

日期：2026-10-11。版本：1.4 / versionCode 5。

## 实现范围

首页新增存档管理，继续沿用绿色 Material 3 主题、系统深色和字体大小。国服、国际服独立选择；国服发现单账号时自动选择，多个账号必须选择。列表显示角色／世界的文件名、大小及修改时间。

支持内置五份主文件、手机多选 .plr/.wld 和 ZIP 暂存导入，确认窗口显示目标服及账号，要求先退出游戏。同名在各目标目录内忽略大小写检查，自动追加递增编号；只修改文件名，不修改内部名称和内容。批次逐项报告实际名称或未完成原因。

单选导出原文件，多选导出按 Players/Worlds 分组的 ZIP，能够再次暂存导入。导出经过系统文档提供方写入、同步及 SHA-256 回读检查。只处理主文件，不修改或打包 .bak、地图探索等附属文件。

## 文件访问

服务新增受限的账号枚举、主文件列表、读取和创建事务。Binder 参数只能选择版本、数字账号及合法主文件名，不能提供任意路径。每个事务继续校验主用户应用 UID 和 shell UID 2000；Shizuku UserService 协议版本升为 3，避免复用旧服务。

国际服目标为包目录下 Players/Worlds，国服目标为 com.xd.terraria 下实际存在的数字账号目录。示例账号 53399 未硬编码。游戏／账号根目录必须存在，只在有效根目录下创建缺失的 Players/Worlds。目录和文件符号链接、路径穿越和非普通文件被拒绝。

同名检查在服务端实际创建时重新执行；独占创建使用 O_CREAT | O_EXCL，遇到创建竞态重试，已有文件不打开写入。存档通过文件描述符流式传输，大小检查、同步、SHA-256 回读通过后才返回成功。常规异常会删除本次新创建的文件，并核对 inode 避免清理别人的文件。进程强杀或设备掉电没有保证新文件原子完成，可能留下未确认的部分新文件；这与原有语言写入的恢复日志是不同的机制，不能把语言事务的恢复保证套用到存档导入。

ZIP 在应用缓存中完成校验后才出现确认窗口，检查实际解压字节而非信任 ZIP 元数据。每文件 64 MB、每批 256 MB、最多 500 份主文件；忽略条目也限制解压总量。批次内相同文件名保持各自内容，由服务顺序分配名称。
